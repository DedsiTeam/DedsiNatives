# DedsiNative React Admin UI / UX 规范

本规范只定义后台界面的视觉、布局和交互边界。业务字段、接口契约和数据刷新流程以真实代码与业务 Skill 为准；运行时 Token 以 `src/react-admin/src/index.css` 为唯一事实来源。

## 页面结构

- 标准分页管理页使用 `CrudToolbar` 和 `CrudTable`，不要在页面重复实现工具栏卡片、表格卡片、分页器和空状态。
- 页面容器采用纵向布局并使用现有 `--space-*` 间距；复杂页面可按信息层级增加标题或说明，但不得复制 CRUD 组件已经提供的容器。
- 新增、编辑和详情保留在业务页面；优先使用 Ant Design `Modal`、`Form`、`Descriptions`、`Result`、`Skeleton` 等成熟组件。
- 树形表格、无限滚动、主从布局等特殊页面可偏离标准分页结构，但需说明原因并复用仍适用的通用组件。

## 搜索、重置与刷新

- 远程搜索默认区分草稿条件和已提交条件，避免输入过程中高频请求；只有需求明确要求即时搜索时才例外。
- 查询和重置只更新筛选状态。筛选变化后回到第一页由 `useCrudTable` 统一处理，页面不得重复维护 `pageIndex` 或调用 `refresh(true)`。
- 重置必须同时清空草稿条件和已提交条件。
- 刷新保持当前页码和筛选条件，调用 `refresh()` 或页面已有的等价加载方法；刷新按钮通过 `CrudToolbar.extraActions` 扩展并展示 loading 状态。
- 所有“新增”“新建”“创建”主操作通过 `CrudToolbar.createButton` 或全局 `create-primary-button` 实现，不在页面重复定义背景、阴影或状态样式。

## 表格与单元格

- 列定义使用 Ant Design Table 标准类型；操作列固定在右侧，采用紧凑 `Space`、文字按钮、语义图标和必要的 Tooltip。
- 删除、重置密码等危险操作使用 `danger` 语义并提供 `Popconfirm`，文案明确说明影响。
- ULID、Guid 等标识统一使用 `CopyableIdTag`；不要在页面重复实现剪贴板调用、等宽标签和成功提示。
- 主体列优先展示清晰的名称；辅助信息使用次要文字并处理溢出。Avatar 仅在能增强辨识度时使用，不作为所有列表的强制装饰。
- 状态使用 Ant Design 语义 Tag；空值统一显示“未填写”或 `-`，不得让 `null`、`undefined` 直接出现在界面。
- 表格在窄屏允许横向滚动；列宽、固定列和文本省略应避免操作按钮被挤压或主体信息不可读。

## 表单与详情

- 新增和编辑字段相近时共用一个表单弹窗；提交期间禁用取消、遮罩关闭和重复提交。
- 简单表单使用单栏，字段较多且存在明确分组时才使用双栏或 section card；不要为了视觉丰富制造无业务意义的分区。
- 表单控件必须有可理解的 label、校验提示和禁用状态。关联选择支持搜索，并在多选时展示已选数量。
- 详情使用 `Descriptions` 或语义清晰的只读布局；只有存在高频后续操作时才在 footer 提供“编辑”等入口。
- 页面保留用户可修正的输入。认证、网络和通用服务端错误由请求客户端处理；页面只补充请求层未覆盖的业务结果，避免重复提示。

## Token、响应式与可访问性

- 十六进制、`rgb()`、`rgba()`、`hsl()` 等字面色值只允许出现在 `src/index.css` 的 `:root` Token 定义区；页面 CSS Module、JSX 和 Ant Design 主题只消费 CSS 变量。
- 间距遵循 4px 基础网格并优先复用 `--space-*`；圆角、阴影、边框和颜色使用已有语义 Token。
- 品牌主操作、选中态、标题区和装饰背景不使用主色渐变、发光或拟物效果。
- 页面样式默认放在同目录 CSS Module；避免大段内联样式、无必要的 `!important` 和依赖视觉结果的类名。
- 窄屏下工具栏自然换行、输入框扩展到可用宽度、弹窗保留安全边距；保持键盘操作、可见焦点、正确标签和足够文字对比度。

## 验证

- 检查 loading、empty、disabled、提交中、失败和窄屏等与本次功能有关的状态。
- 纯 UI 任务不得改变 API 路径、请求参数、业务规则、权限、路由语义或刷新顺序。
- 从 `src/react-admin` 运行 `bun run build`；适用时运行聚焦 lint，并在浏览器检查受影响的桌面与移动端交互。
