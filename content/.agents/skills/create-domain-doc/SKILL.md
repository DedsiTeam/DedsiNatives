# 创建领域文档

为项目 `docs/domains/` 生成结构统一、可评审、可映射到实现的中文 DDD 领域文档。只修改领域文档，不擅自创建实体、接口、迁移、Endpoint、前端页面或工作项。

## 工作流程

1. 将包含 `docs/`、`src/` 和 `AGENTS.md` 的目录作为项目根，读取根目录 `AGENTS.md`。
2. 完整读取 `docs/domains/用户.md`，把它作为唯一格式基准；同时读取目标领域已有文档，避免覆盖用户已有事实。
3. 以用户需求为领域事实的首要来源；用户指定的参考实体、字段清单或文档作为补充事实来源。整理领域名称、聚合根名称、字段、类型、可空性、标识策略、状态和业务行为。
4. 用户明确提出的目标领域设计可以直接写成领域规则，不以 DedsiNative 中是否已有对应实现为前提。对用户和参考资料都没有明确给出的业务规则保持克制：可以提出合理的“建议”或“待确认事项”，不得把未经确认的唯一性、删除策略、权限关系或格式校验写成既定事实。
5. 创建或更新 `docs/domains/{领域名称}.md`。中文文件名与领域名称一致；已有文档应增量完善而不是重写掉已有有效内容。
6. 完成后检查标题、字段类型、代码示例与用户需求及用户指定的参考资料是否一致。

## 固定文档结构

除非领域确实不适用，否则按以下顺序组织：

```text
# {聚合根}聚合根（{Aggregate} Aggregate Root）

引言：说明文档覆盖范围。

## 聚合概览
### 所属分层
### 聚合根定位
### 标识策略

## 聚合成员
字段与领域行为表格。

## 聚合根设计
### 构造函数
### 私有 Setter 与业务方法

## {子实体或值对象}（如适用）

## 领域不变量

## 领域事件（如适用）
### 事件载体
### 事件处理器

## 软删除、审计与敏感信息（如适用）

## CQRS：仓储与查询分离
### 写侧 `I{Aggregate}Repository`
### 读侧 `I{Aggregate}Query`

## 持久化建议

## 数据库迁移（仅在已有迁移事实或用户要求时添加）

## 设计小结
```

## 内容规则

- 聚合根应说明目标所属模块、命名空间、聚合边界和不能绕过聚合修改属性的约束；即使对应实现尚未创建，也可以按用户需求描述目标领域设计。
- 一对多子实体集合应在领域模型中直接使用集合属性（建议 `ICollection<T> Items { get; private set; } = [];`）；领域方法直接调用该属性的 `Add`、`Remove`、`Clear`，不要另建同名私有集合字段或 `AsReadOnly()` 集合视图。文档中的集合成员类型应与实际代码一致。
- 聚合成员表至少包含：成员、类型、可见性、领域语义。
- 字段长度、默认值等可复用约束不得写成聚合实体自身的 `MaxNameLength` 等常量；实现时应在同目录的 `{Aggregate}Consts` 中声明，并由实体、映射和测试统一引用。
- 领域模型主键默认使用 26 位 ULID 字符串，并在标识策略和字段表中明确写出“26 位 ULID”。只有存在明确的系统兼容性、外部接口或数据库约束等特殊情况时，才使用 `Guid` 或其他类型；必须在文档中说明特殊原因，不能仅因习惯或实现方便改变默认策略。
- 标识策略必须准确区分 26 位 ULID、`Guid` 和其他类型；不能沿用模板中的旧类型，也不能把未确认的类型写成既定事实。
- 每个字段说明必填性、长度、可空性、敏感性或默认值；用户未提供的约束标为“建议”或“待确认”。
- 领域行为使用领域语言命名，例如 `ChangeName`、`Enable`、`Disable`、`RecordLogin`，并说明行为维护的不变量。
- 子实体、值对象、枚举、状态转换、领域事件和外键关系只有在用户输入或现有领域事实支持时才加入。
- CQRS 部分必须区分写侧仓储和读侧查询；说明列表/分页使用查询投影，单条详情通过仓储加载完整聚合。
- 持久化建议可以给出表名、字段类型、索引和关系，但必须标记为建议，除非代码或用户需求已确认。
- 密码、身份证号、令牌、密钥、登录 IP 等敏感字段必须说明脱敏、日志和 DTO 输出边界；禁止在文档中写入真实秘密。
- 领域事件只记录必要的不可变快照；外部通知、缓存刷新和同步副作用由事件处理器完成。
- 文档使用中文说明，代码标识符优先使用用户需求或用户指定参考资料中的 C# / TypeScript 命名，不写无关的实现细节。

## 示例映射

用户只提供如下输入时：

```text
权限：Id【Ulid 26长度】，系统Id，权限名称，是否启用
```

应生成权限聚合文档，至少覆盖 ULID 标识策略、系统归属、字段表、启用/停用行为、系统筛选查询、仓储和持久化建议；不能凭空增加角色授权关系或 JWT Claim 实现。

## 完成检查

- [ ] 已读取并遵循 `docs/domains/用户.md` 的结构。
- [ ] 文件位于 `docs/domains/`，文件名与领域名称一致。
- [ ] 字段、类型、主键长度和状态名称与用户输入一致。
- [ ] 聚合边界和领域行为清晰，未把未经确认的建议写成事实。
- [ ] 仓储、查询、持久化和事件部分没有越过领域层的架构约束。
- [ ] 未创建无关代码、迁移、工作项或辅助 README。
