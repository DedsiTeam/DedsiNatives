# 产品需求文件规则

- `docs/product/requirements/` 是 Codex 产品角色的本地需求编写区，保存讨论成稿、评审结论和实施记录。
- 每份文件使用 `docs/product/templates/product-requirement.md` 结构，并保留可机械识别的 YAML frontmatter。
- 待决事项、假设和已确认规则必须分开；未确认的领域语义不得写入编码任务的 Ready 内容。
- 一份需求文件先表达完整产品意图，再列出竖向编码任务；不按数据库、后端、前端等技术层单独拆分。
- 每个编码任务必须包含业务目标、规则、范围、排除范围、契约、依赖和可验证验收标准。
- 本地需求文件是需求、验收标准、评审结论和实施记录的事实来源；需求变化时同步更新状态和日期。
- 文件不得包含 Token、生产连接字符串、客户秘密、真实个人敏感数据或其他凭据。
- 产品角色只写 `docs/product/**`；需求确认不等于开始编码，实施由用户明确发起。
