# 用户聚合根（User Aggregate Root）

本文从领域驱动设计（DDD）角度说明 `DedsiNative.Core` 中的用户聚合根，覆盖聚合边界、不变量、领域事件以及 CQRS 仓储与查询接口。

## 聚合概览

### 所属分层

`User` 位于领域层 `DedsiNative.Core` 的 `Users` 模块，命名空间为 `DedsiNative.Users`。领域模型不依赖 EF Core、FastEndpoints 等基础设施或宿主框架。

### 聚合根定位

`User` 继承 `DedsiAggregateRoot<string>`，是用户聚合的一致性边界和唯一入口。外部代码通过聚合行为修改状态，不能绕过聚合直接设置属性。

### 标识策略

主键类型为 `string`，使用 ULID 字符串作为用户唯一标识。ULID 同时具备全局唯一性和时间有序性，适合分布式场景。

### 聚合成员

| 成员 | 类型 | 可见性 | 领域语义 |
|---|---|---|---|
| `Id` | `string` | 继承自基类 | 用户 ULID，由业务构造函数传入 |
| `Name` | `string` | public get / private set | 用户名称，只能通过 `ChangeName` 修改 |
| `Email` | `string` | public get / private set | 用户邮箱，只能通过 `ChangeEmail` 修改 |
| `ChangeName(name)` | 方法 | public | 修改名称并执行非空守卫，返回当前聚合 |
| `ChangeEmail(email)` | 方法 | public | 修改邮箱并执行非空守卫，返回当前聚合 |
| `MaxNameLength` | `int` | public const | 用户名称最大长度 64，与数据库约束一致 |
| `MaxEmailLength` | `int` | public const | 用户邮箱最大长度 256，与数据库约束一致 |

## 聚合根设计

### 双构造函数

- 受保护的无参构造函数仅供 ORM 反射实例化，业务代码不能用它创建残缺实体。
- 业务构造函数 `User(id, name, email)` 是创建聚合的合法入口，并复用 `ChangeName`、`ChangeEmail` 完成赋值和校验。

### 私有 Setter 与业务方法

- `Name` 和 `Email` 使用 `public get; private set;`，外部不能绕过业务规则直接赋值。
- 状态变更收敛到 `ChangeName`、`ChangeEmail`，以领域语言表达行为。
- ABP 的 `Check.NotNullOrWhiteSpace` 拒绝 null、空字符串和纯空白，并分别限制名称最大 64 个字符、邮箱最大 256 个字符，防止聚合进入数据库无法持久化的状态。
- 修改方法返回当前实例，支持 `user.ChangeName("张三").ChangeEmail("a@b.com")` 形式的链式调用。

> 邮箱格式和唯一性目前尚未形成明确领域规则。在产品确认之前，不应擅自把这两项加入聚合不变量。

## 用户创建领域事件

创建后的副作用通过本地领域事件解耦：

1. 调用方通过业务构造函数创建 `User`。
2. 聚合在名称和邮箱校验完成后调用 `AddLocalEvent(new UserCreatedEvent(Id, Name, Email))`，自动且仅登记一次创建事件。
3. ABP 本地事件总线在工作单元中派发事件。
4. `UserCreatedEventHandler` 通过 `IEmailSender` 执行账户创建通知。

### 事件载体

`UserCreatedEvent` 是不可变的 C# record，保存创建时的标识、名称和邮箱快照，避免处理事件时读取已经变化的聚合状态：

```csharp
record UserCreatedEvent(string UserId, string Name, string Email)
```

文件位于 `Users/Events/UserCreatedEvent.cs`。

### 事件处理器

`UserCreatedEventHandler` 实现 `ILocalEventHandler<UserCreatedEvent>` 和 `ITransientDependency`，由 ABP 依赖注入注册。发送邮件等副作用不进入聚合本体；新增创建后动作时，可以增加独立事件处理器。

## CQRS：仓储与查询分离

### 写侧 `IUserRepository`

```csharp
IUserRepository : IDedsiCqrsRepository<User, string>
```

- 面向用户聚合根定义，一个聚合对应一个仓储。
- 接口声明在领域层，实现位于基础设施层，依赖方向指向领域。
- 承载用户聚合的新增、删除、修改和按 ID 加载等写侧能力。

### 读侧 `IUserQuery`

```csharp
IUserQuery : IDedsiQuery
```

- 服务于查询场景，可直接投影 DTO 或视图模型。
- 避免为了列表和筛选加载完整聚合。
- 与仓储接口共存于 `Users` 模块，保持读写职责清晰。

## 设计小结

| DDD 模式 | 落地方式 | 收益 |
|---|---|---|
| 聚合根 | `DedsiAggregateRoot<string>` 作为一致性边界 | 保持一致性 |
| 封装与不变量 | 私有 Setter、业务方法和 `Check` 守卫 | 防止非法状态 |
| 领域事件 | `AddLocalEvent` 与 `ILocalEventHandler` | 解耦副作用 |
| CQRS | `IUserRepository` 写侧与 `IUserQuery` 读侧分离 | 读写职责清晰 |
